# free5GC lab configs

free5GC (5G SA) is the alternate mobile core for the Fairwave lab: unlike
Open5GS it ships **native per-UE charging** (PFCP Usage Reports from the UPF
to the SMF → CHF, TS 32.255/32.291), so fair-use data caps can be measured
from the core instead of a GTP-U packet tap. It is Go-based like this repo,
stores subscribers in MongoDB like Open5GS, and matches the roadmap's 5G/n48
direction.

This directory holds the NF configs mounted into
`deploy/docker-compose.5g.yml`.

## Layout

## Host prerequisites (the two hard ones)

1. **gtp5g kernel module v0.9.5** — the UPF's data path. The module must be
   loaded on the **host** (the privileged UPF container creates the tunnel
   via it):

   ```bash
   git clone --branch v0.9.5 --depth 1 https://github.com/free5gc/gtp5g.git
   cd gtp5g && make && sudo make install
   ```

2. **AVX** — `mongo:4.4` is pinned on purpose (mongo ≥ 5 requires AVX
   instructions; check with `grep avx /proc/cpuinfo`). If the host lacks
   AVX, keep mongo 4.4.

## How the Fairwave control plane talks to this core

- **SIM provisioning** — `hsswrite` driver `free5gc` (`core/sim-ops/hsswrite/free5gc.go`)
  runs `docker exec mongodb mongosh` against the `free5gc` database and
  upserts the seven UDR collections the webconsole/free5gc-populate use
  (authenticationSubscription, amData, smData, smfSelectionSubscriptionData,
  policyData, identityData). Config: `hss.driver: free5gc`, `hss.container:
  mongodb`.
- **Live sessions** — `collector` source `free5gc` (`core/fairwave-control/
  internal/collector/free5gc.go`) polls the AMF OAM API. Config:
  `core: free5gc`, `collector.enabled: true`, `free5gc.amf_oam_url:
  http://amf.free5gc.org:8000`.
- **Usage (fair-use caps)** — `collector` source `cdr`
  (`core/fairwave-control/internal/collector/cdr.go`) reads the CHF's CDR
  files and reports per-UE byte totals straight from the core: the SMF
  relays PFCP Usage Reports (driven by `urrPeriod`/`urrThreshold` in
  `smfcfg.yaml`) to the CHF, which rewrites one file per subscriber
  (`chf-<sha256(supi)>.cdr`, TS 32.297 container + BER ChargingRecord)
  into its `/tmp`. The 5G compose shares that directory with the control
  plane via the `chf-cdr` volume; set `free5gc.cdr_dir` to its mount
  point and the collector feeds the existing quota/auto-suspend pipeline
  (no GTP-U tap, no CAP_NET_RAW).

  **Deployment requirement:** the CHF only writes CDR files when the SMF
  opens offline charging sessions for PDU sessions, which needs charging
  configured in the PCF — enable slice-level (or flow-level) **offline
  charging** for the `internet` DNN in the webconsole (see
  free5gc.org/guide/Charging/setting). Without rating groups there is no
  `MultipleUnitUsage` in the charging requests and no volume in the CDRs.

  **Reset semantics:** each file is a snapshot of the subscriber's current
  totals, rewritten whole on every usage report. The collector reports the
  absolute totals as session counters; the usage fold in the control plane
  computes deltas, so a snapshot reset (session released, CHF restarted)
  simply pauses counting until the new snapshot grows past the last
  reading — usage totals never decrease.
- Everything north of that (REST API, CLI, dashboard, audit, eSIM) is
  core-agnostic.

## Bringing it up

```bash
./core/free5gc/fetch-upstream.sh          # once: canonical NF configs + certs
docker compose -f deploy/docker-compose.5g.yml up -d
docker compose -f deploy/docker-compose.5g.yml exec ueransim ./nr-ue -c ./config/uecfg.yaml
```

Then confirm the UE shows up in the control plane:

```bash
fairwave sims --server http://localhost:8080   # SIM marked active when attached
```

## Known gaps / next phases

- **Online charging (enforcement at the UPF)**: the CDR path measures usage
  and the control plane suspends over-quota SIMs; CHF online charging would
  enforce quotas in the data plane itself (the UPF drops a flow when its
  rating group is out of quota). That requires quota management in the
  CHF/ABMF (per-SIM balances) rather than the current CDR snapshot.
- free5GC is **5G-only** — the migration is all-or-nothing for the lab; the
  Open5GS stack (deploy/docker-compose.yml) stays for 4G.
- The control-plane container has no docker socket, so SIM issuance **via
  the API** cannot write back to the UDR from inside the compose (the
  handler returns 502 `hss_writeback`). Seed the UDR from the host CLI
  (`fairwave esim issue --hss-driver free5gc --hss-container mongodb`) or
  the WebUI, or mount the docker socket into the control image for
  in-compose write-back.
- CI coverage: `.github/workflows/5g-attach.yml` brings the whole stack up
  (gtp5g module, srsRAN image, free5GC compose), provisions the lab vector
  via the hsswrite free5gc driver, and asserts the UE appears in
  `/v1/sessions`.
